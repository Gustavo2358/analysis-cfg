# ADR-0009 — Binding JSON pertence à especificação AIR

Status: `accepted`. Data: 06/09/2026. Binding upstream: presente/DRAFT.
Adapter no `analysis-cfg`: inexistente.

## Contexto

O modelo Java compartilhado e um formato interoperável têm ciclos de versão e
consumidores diferentes. Serializar automaticamente o layout de records selaria
decisões de uma linguagem dentro do contrato de transporte.

## Decisão

`analysis-ir` possui e versiona o binding JSON da AIR, de modo independente de
linguagem. A candidata **Analysis IR JSON Binding 1.0.0** observada em
`bindings/json-v1.md` targets AIR 2.0.0 e permanece **DRAFT**, portanto ainda não é
um contrato `NORMATIVE`/`ACCEPTED`.
`air-java` permanece sem Jackson/Gson/JSON. Um futuro reader do `analysis-cfg` é
adapter de infraestrutura que converte o binding para a mesma `Publication` do
`air-java` consumida em memória.

Este checkpoint apenas registra a candidata existente; não implementa JSON reader,
writer, schema ou round-trip. A ausência desse adapter não bloqueia a boundary em
memória nem autoriza inferir schema do layout de records Java.

## Alternativas rejeitadas

Tratar JSON do COBOL Semantic Product como AIR; expor DTO/JSON na porta `BuildCfg`;
usar a serialização automática dos records Java como schema normativo; adicionar
dependência de transporte ao `air-java`.

## Consequências e validação

Codec e erros de arquivo ficam fora do kernel. A futura prova arquivo/memória deve
comparar produtos semânticos após ambos entregarem `Publication`, sem mudar porta ou
algoritmo. Evolução do binding não altera a versão semântica AIR silenciosamente.

## Evidência

Decisão explícita do responsável; binding DRAFT no commit AIR fixado
`122ce54e1b9ef9b00646f93ece409ca8b63bc933`; fronteira sem transporte e estado não
implementado documentados pelo `air-java` no SHA fixado.
