# ADR-0015 — File dependencies source-closed

Status: **scope lock aceito pela instrução humana de 16/09/2026**;
desenho de implementação proposto para revisão em FD-H4, sem implementação.

## Contexto e decisão

Estender a pipeline existente com programa → arquivo. O [brief canônico](../../product/file-dependencies/brief.md)
fixa a fronteira `COBOL_SOURCE_ONLY`, a simetria com CALL e os non-goals.
Revisão humana H4: assignment-name prova um external file name, não o mecanismo
DD/environment. Não modelar esse mecanismo, nem como UNKNOWN. N+C são core
obrigatório; D é extensão posterior, sem bloquear W11 (decisão de 2026-09-16).
Conhecimento estável fica nos docs de domínio/produto; estado no handoff; waves
nos work items lean existentes. Não duplicar o discovery nem criar executor novo.

Declarações e usos são produtos distintos. O consumer FILE compartilha sessão,
índices e providers com CALL, com resultados/parcialidade próprios. CALL mantém
suas regras de nomes. Inventário literal não espera solver. JSON terá seção
própria de arquivos e evolução explícita, conforme [auditoria dos readers](../../product/file-dependencies/contracts.md).

Usar recursos/invoke/efeitos AIR existentes para execução. O codec de inventários
tem gap comprovado; associação owner/conector/registro/target ainda exige desenho
bilateral. Não esconder essa associação em displayName/provenance ou sidecar SP.
Escolher em W1 a menor extensão neutra suficiente, se necessária, antes de editar
`analysis-ir`. Este ADR não muda a AIR nem aprova um schema hipotético.

W0 fecha o contrato **SP** de declarações/bindings, independentemente dessa decisão
AIR. A estratégia inicial para unidades é composição por unidade selecionada,
com owners/captures do frontend e agregação explícita em W9; sem atribuir ao pai
I/O exclusivo do filho, sem inferir binding por texto downstream.

## Consequências verificáveis

- Nenhum campo, consulta ou estado de resolução física; ausência de DSNAME não
  diminui completude. Scope guard no catálogo, aplicado a todas as waves.
- Novos efeitos precisam dos oráculos CALL/I/O transversais, incluindo handlers.
- Um Draft PR persistente por repo efetivamente alterado; E2E permanece local.
- `analysis-ir` somente muda por necessidade normativa real; codec faltante não
  implica automaticamente novo conceito na especificação.
- H4 termina em STOP humano. Itens W permanecem TODO; readiness não é execução.

## Decisão final de produto — closeout

CORE N+C concluído e qualificado; W11 pós-EP-R2 revisado humanamente.
W10 = DEFERRED / OPTIONAL_EXTENSION / NOT_PART_OF_CORE /
REQUIRES_NEW_PRODUCT_AUTHORIZATION. Não é requisito nem gap do produto mainframe.
Merges topológicos, repins equivalentes e smoke final autorizados. A proposta
histórica acima foi concretizada por D-AIR (resource.bindings@1), wire2.3 e
consumer FILE independente; ver [closeout](../../product/file-dependencies/closeout.md).
