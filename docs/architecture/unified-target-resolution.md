Rule: qualification establishes whether an occurrence contributes; target resolution
uses its actual subject, BEFORE point and provider admission. An unrelated Region
cannot route a logical Cell away from an admitting scalar provider. Batch queries
per Entry/provider and share results across executable and source supports.

The product input explicitly binds AIR, qualified-source-dependencies 1.0.0 and
existing typed StatementLinks to content digests. A source occurrence without an

Oracles: scalar routing with 0/1/100/1000 unrelated Regions, real logical expression
chain, no values for literals, intrinsically regional queries, scalar refusal,
overwrite/snapshot, source/executable deduplication, digest/identity rejection,
and unchanged SP/AIR/CFG. CP0 cases retain their original classification.

No new solver, duplicate text interpreter, automatic physical fallback, control
semantics or changes to AIR/IR are authorized. Provider preparation is finite over
indexed operations and query demand; execution keeps the existing fixed-point solver.

## Implementation and limits

DependencyInput admits the certificate and typed links before query planning.
QualifiedDependencyOccurrence carries the shared identity and target descriptor.
TargetResolver owns program name interpretation and combines the already queried
site results with the source authority. Its output directly supplies the canonical
inventory; the source projection delegates the same literal interpretation.

CallDependencyPlan probes each distinct Entry/subject scalar demand. Admitted
subjects share one scalar run per Entry. Refused objects use the existing wider
provider; physical range/choice subjects use StorageValues. If both wider shapes
occur, their already-wider demands share the storage projection of the same engine.
Accepted scalar demands never change provider because another query is physical.

The scalar preparation ignores unused unsupported declarations, scopes operations
to the selected Entry units and closes demands over logical reads. Actual unsupported
effects remain refusals, including effects through unmodeled aliases. Unproved
operations in the demanded transfer cannot claim strong replacement. Historical
logical test fixtures now declare their fixed text bounds with FitText, matching
lower's logical representation; expected values and provenance were not relaxed.

Expression provenance propagates only supports associated with the captured input
alternative, remapped onto the derived value. Values, overwrite and snapshot rules
are unchanged. No regional logical evaluator was extended.

Preparation is finite over indexed operations, demanded objects and expression reads.
The existing solver runs once per distinct Entry/provider/options demand batch.
Provenance is a finite set of existing producer identities per logical value. Costs
are measured separately for admission, planning, solving and corpus commands.
Unsupported effects or storage within a demanded closure can still refuse scalar
admission; a refusal is preserved and does not enable physical mode automatically.

The physical-disabled diagnostic is attached only to a selected wider query whose
resolved storage bounds include a Region. A scalar query or an unsupported logical
Cell does not inherit the diagnostic from another query in the same Entry.
