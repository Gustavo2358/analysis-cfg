## W1 rule and contract

Missing executable completion evidence is not a negative proof about a source
candidate. Preserve the existing executable ControlTopology outcomes unchanged.
The frontend may separately publish a source-only possible completion, derived
from the grammar-owned continuation and carrying CONTROL_POSSIBILITY evidence.
This is a hypothesis, not LOCAL_GRAMMAR executable return authority. Known
terminal/transfer statements do not acquire ordinary completion this way.
The source inventory retains unresolved external effects and nonreturn as open.

SP2.52 introduces optional sourceContinuations with statement, target, proof
references and optional prerequisite occurrences. Old documents have none. Targets and proof identities are validated
through both typed and wire ports. Only the source-evidence projection consumes
them. Executable AIR emission, handler admission and CFG projection ignore them.
Historical SPs retain their interpretation; source should be regenerated to gain
new producer evidence. The continuation uses region completion binding, never
physical statement order inferred downstream.

The existing finite source/state engine is reused in an explicit source-only
mode. Crossing a possible completion retains a frontier and adds a derivation
with the hypothesis proof. A source certificate carrying such proofs uses the
new qualified-source-dependencies version 1.1.0. Version 1.0.0 rejects that proof
kind; legacy bytes and semantics remain unchanged.

Consumers distinguish nodes with only hypothetical derivations from nodes carrying
any hypothetical alternative. Public uncertainty uses the latter: an executable
branch at an IF join cannot refute values arriving through an unknown branch. A proof
reference remains attached to the certificate. No consumer interprets opaque
identity strings as control. Literal and nominal computed values retain operand,
assignment, seed and uncertainty provenance; unsupported values are not invented.
Positive executable results and valid kills keep their existing authority.

## Algorithm and limits

Source traversal is finite tabulation over published statements, bindings and
handler states. This wave does not change recursive executable activation.
Grounded-without-assumption analysis is a finite worklist over derivations,
excluding derivations whose proof closure includes CONTROL_POSSIBILITY; caller
premises are conjunctive and alternative derivations disjunctive. Complexity is
bounded by the certificate inventory plus existing source tabulation; no concrete
path enumeration. Unknown procedure structure stays open. Do not create a
whole-program bag of literals or synthetic executable edges.

## Oracle before implementation

The existing ASKTIME/SQL UPDATE/comment/DATASET probes contain CALL AFTERIO with
empty candidates after an unknown SP completion (RED). Inserting unknown control
must retain that candidate with an explicit source assumption, while preserving
AIR/CFG destinations. Computed target copy/snapshot and exact overwrite must obey
nominal semantics. GOBACK/known transfer dead code, unused paragraphs, handler
registration/cancel, model assumptions, invalid references, and old-version
rejection are mandatory negatives. Corpus support/provenance comparison is
required because this changes generic source dependency interpretation.

## Open local control state

A second D9 cause is loss of control-state knowledge: treating an unmodeled
control mutation as ordinary completion does not establish that later branch
destinations remain fixed. The producer recognizes this loss at the grammar
boundary, without interpreting any ALTER target, update, ordering or runtime
execution. Source continuations may therefore carry one prerequisite occurrence.
For an affected unit, a simple transfer's local paragraph destinations remain
unrefuted only under both the transfer and mutation qualifications. The source
engine emits an AND derivation with both premises; if the mutation or transfer
is unreachable, it emits none. It preserves the existing activation/boundary
binding. GOBACK within a destination still excludes subsequent instructions.

This is a coarse source possibility envelope. It deliberately does not prove
that mutation and transfer lie on the same concrete path or resolve an ALTER
assignment. No executable topology/AIR/CFG edge changes. The frontend enumerates
M × T × P source hypotheses (mutations, simple transfers, local nondeclarative
paragraphs); the finite source engine indexes their prerequisites and transports
qualified derivations. This bound and the additional uncertainty are explicit;
there is no source-size threshold or fixture/program-specific target table.
The recursive executable lowering remains outside W1/W6 authorization.

## Mixed alternatives and validation contract

A closed executable value query describes only the executable subset. If the
source certificate has an unknown-control alternative, nominal values are also
queried and carry UNKNOWN_CONTROL_CAN_COMPLETE. An exact subsequent MOVE still
kills older nominal values; FIRST/SECOND joined alternatives and a later FINAL
overwrite have independent adversarial oracles.

Chaos keeps its executable manifest unchanged. Four ALTER-policy fixtures acquire
conditional source alternatives whose assignment locations are independently
listed in chaos_source_possibility_oracle.py. The original executable result and
physical supports remain required, with exact extra names, provenance, open
control and 28 negative mutations checked by the evolved source oracle. This
evolves the source-only abstraction; it does not implement ALTER execution.
