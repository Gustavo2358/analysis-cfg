# EP-W4 — entry coexistence and partial dependency publication

## Rules before production

AIR entry.possibilities@2 already permits simultaneous possible contributions,
including unknown separation and overlap, without turning them into mandatory
initial values. Boundary initialization must be independent of condition order.
Preserve/external unknown add uncertainty; they cannot overwrite source support.
Strong literal contradictions remain the AIR validator's global rejection.

Dependency preparation must preserve independent completed consumer facts when a
values profile is unsupported. A failed semantic obligation yields an explicit
partial site/result, not disappearance. Missing value evidence contributes no
computed candidate. Literal target evidence does not require a values solver.
An unavailable observation must be localized before the consumer staging bundle
is discarded. Genuine inconsistent provider data is still an error.

CFG semantic/capability limits can leave graph execution unknown while
the AIR still inventories literal target occurrences. Such occurrences may be
published as structural source evidence with UNKNOWN reachability and an open
control remainder. They must never be labeled unreachable or graph-proved.
This uses the same target interpreter and existing AIR occurrences, not a second
solver or the separate observed-dependencies product. Invalid AIR remains a
global failure; incomplete structural validation, runtime/resource and I/O errors are not silently relabeled success.

## Explicit result contract change

Dependency JSON 1.2.0 adds preparation status and per-site analysis reasons, and
allows UNKNOWN reachability. Site metadata/candidate support remain mandatory.
Partial literal occurrences carry source-supported candidates with open remainder;
computed sites without a completed value observation remain open with no invented
literal. Edges from UNKNOWN reachability, if retained, are explicitly open possible
dependencies; proved-unreachable sites still have no edges/candidates. Complete
legacy results retain their 1.1.0 representation. No AIR normative change is needed.

## Algorithm and qualification plan

Entry contributions are combined in the existing boundary state, preserving strong
literal consistency and unioning possible support once. Transfer/kill policy is
unchanged. Completed planner facts are retained, and unmatched selected AIR sites
receive explicit partial facts with recorded failure reasons. Existing reachability
observations are reused; unknown control is never guessed from physical order.
The traversal is O(indexed sites + prepared observations + output), with no dataflow
rerun per site. Structural-only fallback is O(AIR occurrences × declared entries),
which is also its output size; it cannot evaluate computed values.

RED oracles: possible entry plus preserve in both orders; two possible entries on
one region/unproved bases; literal DIRECT plus computed unsupported preparation;
literal source with unsupported finite control; contradictory strong initials and
invalid references as rejection controls. Boundary and independent JSON tests must
verify the fact/reason/remainder, not merely successful CLI exit.
